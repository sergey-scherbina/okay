# cats-effect-instances — an okay program as cats-effect's `F`

Status: done, 2026-10-02. Owner lane: `cats-effect-instances`.
The main gap of the cats-depth audit (backlog okay-cats).

## Goal

Code written `F[_]: Async` (http4s, doobie, fs2, most of typelevel) runs
AT an okay program monad, with no `IO` in the user's types:

```scala
opaque type Program[A] = A ! CatsFx + Async   // in object CatsEffect
given programAsync: Async[Program] with LiftIO[Program]   // its companion: no import
def toIO[A](p: Program[A]): IO[A]
def lift[A](p: A ! Async): Program[A]
```

## Design

- **Binds are okay's tree; cats-effect's primitives are an EFFECT.**
  `CatsFx[A]` is one operation: "given the interpreter, build an
  `IO[A]`". `uncancelable`, `canceled`, `onCancel`, `start`,
  `racePair`, `sleep`, `cont`, `evalOn`, `ref`/`deferred` are each one
  `CatsFx`, their sub-programs interpreted lazily inside the IO they
  build.
- **One fiber.** `toIO` is `foldMap` into `IO` (stack-safe, measured in
  effects-foldmap): the whole program runs in ONE IO fiber, so masking
  and the cancellation flag live where cats-effect keeps them. The
  refuted alternative is delegating each operation to its own IO round
  trip (`fromIO(ioOp(toIO(fa)))`): a `canceled` inside `uncancelable`
  would run in a fresh unmasked fiber and cancel the wrong thing.
- **In the row, not hidden in `Async.Run`.** A program needing
  cats-effect's runtime says so in its type; okay's own runners refuse
  it at compile time (no handler for `CatsFx`) rather than throwing.
  okay's `Async` operations inside it interpret as `IO.delay`/`IO.async`
  (with the canceller), and a plain `A ! Async` widens in.

## Behavior

- [x] cats-effect-laws `AsyncTests[Program].async` hold (110
      properties), programs generated by the kernel-testkit's generators
      over OUR instance, compared through `toIO` under a deterministic
      `Ticker`
- [x] masking: `canceled` inside `uncancelable` is deferred to `poll`
- [x] generic code at `Program`: a `Resource` releases on cancel; an
      `F[_]: Concurrent` race and `Ref`; `F[_]: Temporal` timeout
- [x] okay's own `Async` operations inside a `Program` (an `await` with
      a canceller) run and cancel through the interpreter; a 100 000-bind
      okay program lifts in and runs

## Decisions

- **`Program` is OPAQUE (in object CatsEffect), like `Par`.**
  Transparent, it is also an `A ! F`, and the default program monad of
  CatsInterop.scala answered `cats.Monad[Program]` beside the new
  instance: ambiguous on every `traverse`. Refuted first, in order:
  - a negative row test on the default given,
    `NotGiven[CatsFx[Any] <:< F[Any]]`: a using clause there broke cats'
    partial unification, and `mapN`/`traverse` over EVERY program
    stopped compiling (TestCatsInterop, TestLaws);
  - the instance behind its own import, relying on the nearer scope
    winning: `Isomorphisms.invariant` still found both, ambiguous.
  Opaque, the type has one instance, found in its companion with no
  import; the price is `CatsEffect.lift` at the door.
- **`toIO` walks the tree; it is not `foldMap`.** `foldMap` closes with
  `/ pure`, a `flatMap(IO.pure)` after the last operation, which is a
  cancellation point inside an enclosing `onCancel` after the mask came
  off. cats-effect-laws' "onCancel associates over uncancelable
  boundary" failed on exactly that (231 of 232 passed). The walk makes
  one operation exactly its IO and one bind exactly one `flatMap`.

## Results

- okay-cats 323 tests green, twice in a row (the laws draw fresh
  programs each run): 110 `AsyncTests` properties, 6 generic-code tests,
  2 resolution tests, the rest unchanged.
- Mutant: `uncancelable` without the mask fails the masking test and 5
  laws ("canceled sequences onCancel in order", "uncancelable eliminates
  onCancel", "uncancelable race not inherited", …).
